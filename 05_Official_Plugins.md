# Official Plugins

Официальные плагины — базовый набор инструментов Верстака. Они используют тот же
plugin runtime, что и сторонние. Их задача — показать, что платформа работает
через capabilities и contribution points.

Все официальные плагины используют префикс `verstak.*` в id.

## 1. `verstak.files`

Назначение:

- дерево/список файлов внутри дела;
- добавление файлов и папок;
- перемещение/переименование;
- открытие через Workbench (openProvider routing);
- trash/restore (через `verstak.trash`);
- file metadata.

Provides:

```
workspace.files
vault.files
entity.file
file.browser
```

Optional requires:

```
editor.text
viewer.file
preview.file
search.provider
```

Текущий статус: реализован. Открывает файлы через `api.workbench.openResource()`,
не импортирует редактор напрямую. Поддерживает безопасное копирование и
перемещение файлов и папок между Делами через core Files API; перенос на Дело
использует уже существующую папку `Files`. Корзина выделена в отдельный плагин
`verstak.trash`.

## 2. `verstak.notes`

Назначение:

- markdown notes как UI-слой над обычными `.md` файлами;
- каноническая папка `Notes/` внутри дела;
- `Overview.md` — обычное markdown-имя файла, не специальная UI-сущность;
- note metadata;
- rename с синхронизацией title/filename;
- conflict dialog при конфликте имён.

Provides:

```
workspace.notes
note.registry
```

Requires:

```
verstak/core/files/v1
```

Optional requires:

```
editor.text.markdown
search.provider
```

Текущий статус: реализован. Title и filename синхронизированы. При конфликте
имени показывается conflict dialog.

С desktop v0.3.2 и набором плагинов v0.2.6 Обзор Дела предлагает до трёх
последних изменённых заметок с реальным временем изменения файлов. Карточка
открывает именно указанную заметку, а общий счётчик — список заметок.
Ключевой ресурс `Overview.md`, если он присутствует, также открывает свой файл.
Если файл уже перемещён или удалён, остаётся список с понятным сообщением;
чужое Дело по запросу карточки не открывается. Заметки без корректной даты
изменения не используются как кандидаты продолжения работы.

## 3. `verstak.default-editor`

Назначение:

- редактирование текста и markdown;
- toolbar;
- save flow;
- dirty state;
- markdown preview (встроен, не отдельный плагин);
- keyboard shortcuts (Ctrl+S).

Provides:

```
editor.text
editor.text.markdown
editor.note.markdown
```

Optional requires:

```
link.resolver
```

Текущий статус (плагины v0.1.5, desktop v0.2.5): реализован как единый плагин с
тремя openProviders (`text`, `generic-markdown`, `notes-markdown`) на CodeMirror 6,
собранном в бандл плагина. Использует `api.files.readText` / `api.files.writeText`.

- Режимы «Редактировать», «Чтение» и «Рядом». Документ, история правок, выделение
  и прокрутка переживают переключение режимов; в чтении нет панели форматирования.
- Undo/redo (Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z) по физическим клавишам, в том числе
  в русской раскладке; форматирование и замены — отдельные шаги истории.
- Ссылки на заметки: кнопка «Ссылка на заметку», Ctrl+K или ввод `[[`. Алиасы
  сохраняют старые ссылки рабочими после переименования; неоднозначная ссылка не
  открывает произвольную заметку. Обратные ссылки показываются с контекстом.
- С desktop v0.3.1 и набором плагинов v0.2.5 кнопка с ключом вставляет ссылку
  на секрет текущего Дела или общий секрет. Выделенный текст становится подписью
  ссылки; логин и пароль в Markdown не вставляются.
- Чтение — CommonMark/GFM с привязкой к исходным позициям: чекбоксы задач
  переключаются прямо в просмотре и точечно пишутся в Markdown; оглавление,
  подсветка и копирование кода, таблицы, вложенные списки.
- Черновик сохраняется при ошибке записи и восстанавливается после
  переоткрытия; изменение файла извне показывается предупреждением.
- С desktop v0.3.3 и плагинами v0.2.7 последний черновик сохраняется и при
  немедленном уходе из редактора, включая незавершённую предыдущую запись.
  Восстановленная правка открывается для редактирования, даже если заметку
  открыли для чтения или восстановили после конфликта с внешней версией.
  Восстановление само по себе не изменяет исходный файл; правку можно
  сохранить действием «Сохранить».
- Перенос длинных строк включён по умолчанию; переключатель хранится в namespace
  плагина и не меняет файл.

## 4. `verstak.file-preview`

Назначение:

- metadata view;
- `Open External` через `api.files.openExternal`.

Provides:

```
viewer.file
viewer.image
preview.file
```

Текущий статус: базовый рендеринг изображений через публичный Files API,

## 5. `verstak.activity`

Назначение:

- сбор activity events;
- отображение истории активности;
- реконструкция работы;
- worklog suggestions для Journal.

Provides:

```
activity.log
activity.provider
activity.reconstruction
```

Subscribes:

```
file.opened
file.changed
note.saved
action.started
browser.capture.received
case.selected
```

Текущий статус: с desktop v0.2.0 — фоновый провайдер без собственной вкладки,
пункта в сайдбаре и команды в палитре. Его данные видны через Журнал (предложения
worklog) и через обзор Дела. Предоставляет `activityProviders`; desktop runtime
записывает события в plugin storage без смонтированного вида. Записи хранятся по
UUID Дела.

Команды регистрируются в `activate(api)` — bundle-level hook, который shell
вызывает один раз без монтирования вида. До этого обработчики жили только внутри
`mount()`, и Журнал мог дотянуться до предложений ровно тогда, когда
пользователь смотрел на Активность вместо Журнала.

Команды:

```
verstak.activity.suggestWorklog          — возможные записи журнала
verstak.activity.listBrowserActivity     — записанное время по страницам
verstak.activity.assignBrowserActivity   — Дело, открепление или «не работа»
verstak.activity.listBrowserActivityRules
verstak.activity.setBrowserActivityRule
verstak.activity.removeBrowserActivityRule
```

Время браузера приходит не привязанным ни к чему: расширение не знает, ради
какого Дела открыта страница. Активность решает это тремя способами, в порядке
приоритета: ответ пользователя, правило по адресу, предположение по соседним
во времени событиям одного Дела. Предположения не делаются, когда рядом два
Дела. Каждая запись несёт `assignedBy`, и правило никогда не переписывает
ответ, данный руками.

Предложение несёт разбивку по видам работ, минуты которой в сумме дают общее
время, и признак `guessed` — по нему Журнал спрашивает, а не утверждает.

## 6. `verstak.journal`

Назначение:

- ручной журнал работ;
- billable/non-billable;
- приём suggested time из activity;
- создание записи из завершённого todo.

Provides:

```
worklog
journal
report.worklog
```

Optional requires:

```
activity.reconstruction
```

Текущий статус: реализован как глобальный sidebar view и workspace item.
Спрашивает предложения у всех, кто объявил contribution point
`worklogProviders`, а не у Активности по имени; дедуплицирует по Activity
suggestion id.

Хранение: записи лежат в самом Деле, по обычному Markdown-файлу на месяц —
`<Дело>/Журнал/2026-07.md`. Это документ, а не настройка: его открывает любой
редактор, и синхронизация несёт его вместе с остальными файлами vault. Раньше
журнал жил в plugin settings namespace, то есть под `.verstak`, куда сканер
синхронизации не заходит по устройству.

Текст записи принадлежит пользователю. Комментарий в конце записи хранит только
то, у чего нет читаемой формы, — идентификатор записи и то, из чего она сделана.
Где оба говорят об одном, побеждает текст: правка «45 мин» на «90 мин» в
редакторе — это решение пользователя, а запись, написанная в файле руками и без
всякого комментария, — полноценная запись журнала.

Журналы, написанные до перехода, переносятся в Дело при первом чтении. Копия в
settings остаётся на месте; отметка о переносе не даёт прочитать её второй раз —
иначе удалённая запись возвращалась бы при следующем запуске.

Сохранение журнала помечено как служебная запись (`service` в опциях записи
файла), поэтому оно не превращается в активность, из которой родится
предложение записать в журнал факт записи в журнал.

Отчёт (`report.worklog`). К фильтрам добавлен период — неделя, месяц, прошлый
месяц, год или точные даты, — и он сужает список так же, как остальные фильтры.
Кнопка «Отчёт» вместо списка показывает итог: всего, к оплате и не к оплате,
затем Дела, начиная с того, на которое ушло больше времени, и работа внутри
каждого.

Отчёт сохраняется в vault двумя кнопками: Markdown — читать и отправлять, CSV —
для того, что выставляет счёт. Отчёт по одному Делу ложится рядом с его
журналом, отчёт по нескольким — в `Отчёты/` в корне vault. Сохранённый файл
сразу открывается. Это документ, который попросил пользователь, поэтому его
запись служебной не помечается.

Глобальный список показывает все записи и все предложения с фильтрами по Делу,
отметке к оплате и источнику записи. Предложение с угаданным Делом
показывается вопросом — «Да, <Дело>» / «Другое Дело…» / «Не работа», — и любой
ответ пишет правило про адрес страницы.

## 7. `verstak.browser-inbox`

Назначение:

- приём страниц, ссылок, выделенного текста и файлов из browser extension;
- pending queue с scoping по workspace;
- domain bindings;
- конвертация inbox entry в note/link/file;
- запись конвертаций в Activity.

Provides:

```
capture.browser
browser.inbox
domain.binding
```

Requires:

```
network.local
```

Optional requires:

```
workspace.notes
activity.log
search.provider
```

Текущий статус: реализован как глобальный sidebar view и workspace item.
Local receiver в paired mode с токеном. Поддерживает конвертацию в note
(через публичный Files API), link (`.url` файлы), text file attachments
и bounded binary attachments. Конвертации записываются в Activity.

С Desktop v0.3.4 / official plugins v0.2.8 кнопка «Добавить материал»
позволяет сохранить ссылку HTTP(S), текст или оба поля без расширения браузера.
Название необязательно. В глобальном разделе можно выбрать Дело или оставить
материал без привязки; во вкладке Дела используется текущее Дело. При ошибке
введённые данные остаются в форме, повтор сохранения обновляет ту же запись.
Сохранение использует атомарный `settings.upsertRecord`, поэтому поступления
из расширения не затираются. На старых хостах без этого метода кнопка скрыта.
Очередь Browser Inbox остаётся локальной для устройства; созданные из неё
заметки и файлы синхронизируются обычным способом.

## 8. `verstak.search`

Назначение:

- workspace-scoped search;
- поиск по мере ввода;
- поиск по именам файлов/папок и содержимому текстовых файлов;
- persistent search index;
- cross-provider runtime hosting.

Provides:

```
search
search.provider
search.indexer
```

Текущий статус: реализован как workspace item и `searchProviders` contribution.
Ищет по мере ввода, индексирует vault, обновляет индекс по файловым событиям,
поддерживает других search providers через runtime.

## 9. `verstak.secrets`

Назначение:

- защищённое хранилище доступов;
- workspace-scoped secrets;
- master password (AES-GCM).

Provides:

```
secret-store
secrets.read-ui
secrets.write-ui
```

Текущий статус (desktop v0.3.1, плагины v0.2.5): реализован. Desktop core
предоставляет AES-GCM secret store; плагин показывает общие секреты и секреты
Дел, поддерживает редактирование, удаление и копирование Markdown-ссылок.

Ссылку можно вставить кнопкой с ключом в редакторе. Например, в заметке
«Сайт. Админка: логин/пароль» достаточно выделить «логин/пароль» и выбрать
секрет. Ссылка `verstak-secret://...` открывает компактное окно поверх заметки.
В нём логин и значение можно выделить или скопировать отдельными кнопками.
«Изменить» разблокирует поля в этом же окне; сохранение сохраняет ID секрета
и привязку к Делу, а ошибка записи оставляет введённые значения в форме.

Мастер-пароль запрашивается один раз до завершения приложения или
переоткрытия/смены vault. Enter отправляет пароль. После закрытия окна
фокус возвращается на ссылку; окно поддерживает обе темы. Markdown хранит
только ссылку, значения секретов автоматически не попадают в настройки и
журнал приложения.

Если пароль забыт, «Забыли мастер-пароль?» после явного подтверждения
сохраняет весь зашифрованный каталог в
`.verstak/secrets-archives/<timestamp>-<unique>/secrets` и позволяет завести
новое пустое хранилище с другим паролем. Старые записи не расшифровываются:
для архива всё ещё нужен старый пароль. Старые ссылки не открывают архивные
записи. При ошибке архивирования исходный каталог остаётся на месте.

При создании секрета выбор Дела доступен сразу после разблокировки, включая
вложенные Дела. Организационные папки не считаются Делами. Текущее Дело и
привязки существующих секретов остаются доступны, даже если временно не
удалось получить список Дел.

## 10. `verstak.todo`

Назначение:

- списки задач внутри дел и глобально;
- статусы: open, done, cancelled;
- приоритеты, due date, reminders;
- создание Journal записи из завершённого todo.

Provides:

```
workspace.todo
```

Текущий статус: реализован. Reminders с нативными desktop-уведомлениями
(при наличии capability `verstak/core/notifications/v1`). Поддерживает
создание Journal записи из todo с копированием фактических данных. Список Дел
получает через семантический workspace API и включает только Дела, где
`verstak.todo` разрешён в metadata.

Синхронизация: `todos:global` объявлен набором записей с полем `id`. Список
переносится между устройствами по записи, поэтому задача, добавленная на каждой
машине, остаётся на обеих. Вид перечитывает список по событию
`plugin.records.changed`, а не ждёт следующего открытия.

Назначение:

- шаблоны дел при создании;

снимком включённых инструментов, но не знает, какие плагины за ними стоят.
Действия с шаблонами защищены от случайного удаления (desktop v0.2.3).

## 14. `verstak.import`

Назначение:

- импорт актуального содержимого DokuWiki и Obsidian из выбранной папки или
  архива;
- анализ без записи в vault;
- предложение редактируемой структуры папок, дел, заметок и файлов;
- применение только после явного подтверждения пользователя.

Provides:

```
verstak/import/v1
```

Requires:

```
verstak/core/import/v1
```

Плагин открывается через **Plugin Manager → Import → Settings** и проводит
пользователя через четыре шага: выбор источника, анализ, проверка структуры,
импорт. Предложение адаптивно сохраняет смысловые ветви, распознаёт простые
проектные деревья, а несгруппированные материалы помещает в дело `Без папки`.
Пользователь может переименовать узел, изменить его тип или исключить его до
применения плана.

DokuWiki импортирует только текущие `data/pages/**/*.txt` и `data/media/**`.
История и служебные данные не включаются. Страницы переводятся из wiki-разметки
в Markdown: заголовки, списки, таблицы, горизонтальные линии, code/file и
nowiki-блоки, базовое inline-форматирование, внутренние/внешние ссылки и media.
Три неизменённые штатные страницы актуального релиза DokuWiki
`2025-05-14b "Librarian"` исключаются только при совпадении пути и SHA-256;
изменённые пользовательские версии сохраняются. Неизвестный plugin-синтаксис,
interwiki и неразрешённые ссылки остаются видимыми и сопровождаются
предупреждением.

Obsidian импортирует Markdown и обычные файлы vault, но молча исключает
`.obsidian`. Wiki links, aliases, headings, block references и embeds
переписываются в относительные Markdown-ссылки с учётом итогового плана;
неоднозначные и отсутствующие цели остаются без разрушительного угадывания.
Вложенные архивы считаются обычными файлами.

Каждый запуск создаёт отдельную папку
`Импортировано/<DokuWiki|Obsidian> — YYYY-MM-DD HH-MM-SS`; при совпадении имени
добавляется `(2)`, `(3)` и далее. Плагин показывает одно общее предупреждение,
что импорт может содержать логины, пароли или другие приватные данные. Такие
страницы обрабатываются как обычные: плагин не ищет, не перемещает в Secrets и
не удаляет их.

Текущий статус: реализован как официальный settings-плагин. Поддерживаются
только актуальные структуры DokuWiki и Obsidian; старые форматы отдельно не
эмулируются.

## 15. `verstak.projects`

Назначение:

- роль «Проект» для Дела: описание, статус, даты, приоритет, теги;
- глобальный портфель «Проекты» по всем Делам с этой ролью.

Provides:

```
verstak/project-meta/v1
```

Текущий статус (с desktop v0.1.7): Project Meta — необязательная конфигурация
одного Дела, а не вложенный контейнер. Модель `Дело → Проект → ресурсы` из
v0.1.4–v0.1.6 удалена; все ресурсы принадлежат Делу по его UUID (см.
`verstak-desktop/docs/DEAL_ONLY_SCOPE.md`). Портфель показывает только Дела с
включённой ролью и открывает выбранное Дело по UUID. Если в Деле включены и
Проект, и Milestones, этапы показываются разделом внутри Проекта.

## 16. `verstak.milestones`

Назначение:

- этапы и сроки внутри Дела.

Provides:

```
verstak/milestones/v1
```

Текущий статус: самостоятельный плагин Дела, не зависит от Проекта. Без
Проекта работает как отдельная вкладка Дела; с Проектом встраивается в него.
Legacy-этапы вложенных проектов перенесены миграцией `deal-only-v1`.

## 17. `verstak.git`

Назначение:

- Git-репозитории, подключённые к Делу;
- клонирование или подключение существующего checkout;
- ветка, состояние рабочего дерева, изменённые и неотслеживаемые файлы,
  ahead/behind, последние коммиты;
- fetch, pull только fast-forward, push.

Provides:

```
verstak/git/v1
```

Текущий статус (с desktop v0.1.7): одно Дело может вести несколько репозиториев.
Синхронизируются только дескрипторы репозиториев; рабочие копии
`<Дело>/Repositories/**` вместе с `.git` остаются на устройстве и исключены из
обычного Sync — на втором устройстве репозиторий виден как «не склонирован здесь».
Учётные данные — ссылки на Secrets, которые разрешаются только на время операции:
HTTPS через временный askpass, SSH-ключи через временные защищённые файлы. Сырые
учётные данные не попадают ни в дескрипторы, ни в тексты ошибок.

## 18. `verstak.actions`

Текущий статус (Desktop v0.3.5 / official plugins v0.2.9): Actions 2.0.
Общий раздел в боковой панели и вкладка каждого Дела показывают компактные
карточки запуска программ, скриптов с явным интерпретатором и HTTP(S)-ссылок.
Консольные команды показывают результат и поддерживают остановку; GUI-программы
могут запускаться без ожидания закрытия. Управление появляется при наведении
или фокусе, иконки выбираются в общем поиске, аргументы вводятся строкой с
кавычками и передаются программе отдельным массивом без неявного shell.

Provides: `actions.launcher`. Requires: `verstak/core/processes/v1`.
Permissions: `process.spawn`, `external.openURL`, `storage.namespace` и
обычные разрешения регистрации UI/команд и подписки на события.

Сохранённые через форму действия считаются доверенными на этом устройстве.
Новое внешнее определение или изменение программы, аргументов либо рабочего
каталога через синхронизацию/импорт требует одного подтверждения при запуске.
Название и иконка доверие не меняют. Необязательная настройка «Спрашивать
подтверждение перед каждым запуском» действует и для собственных команд.

Определения переносятся существующими plugin record operations; локальные
SHA-256 записи доверия хранятся через `storage.local` вне vault и не переносятся
на другое устройство. Импортированные `approved`/`trusted` доверие не выдают.
Существующие определения совместимы; без локальной записи доверия потребуется
одно подтверждение. Загрузка, импорт, синхронизация и открытие Дела ничего
не запускают автоматически. Выключение плагина сохраняет определения.

Пути к программам могут отличаться между устройствами; отдельного сопоставления
путей пока нет. Не следует сохранять секреты в определениях. Интеграция
SSHKeeper в этот выпуск не входит.

Подробности: [Actions README](https://github.com/mirivlad/verstak-official-plugins/blob/v0.2.9/plugins/actions/README.md).
